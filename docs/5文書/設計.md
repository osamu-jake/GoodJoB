# 設計 — 知の越境検索（PROJECT ZERO / W6）

仕様を「どう作るか」に落とす。仕様に無いものは足さない。各項目に根拠（仕様の見出しか要件ID）を付ける。
前提：Streamlit単一プロセスのPoC。Next.js/FastAPIのような層分離はしない（仕様「全体像」）。

## 構成

```
app.py                      -- エントリーポイント。起動時にDB自動構築を呼び出し、st.tabs()でタブ①②を切替
ui/
  tab_search.py              -- タブ①検索：検索窓・立場切替・検索方式トグル・カードリスト描画
  tab_techdb.py               -- タブ②技術データベース：一覧・絞り込み・詳細画面
  cards.py                    -- 検索結果カード1件分の描画（関連度%・要約・ハイライト・権利状況・実績）
search/
  cross_search.py             -- cross_search()：BM25＋ベクトル取得→RRF統合
  bm25.py                      -- FTS5（unicode61）での検索、Janome＋品詞フィルタのトークナイズ
  vector.py                     -- multilingual-e5-smallのロード・エンコード・コサイン類似度計算。
                                   フィールド別ベクトルに対して計算し、doc_idごとに最大値へ集約（ADR-0021）
  rrf.py                         -- Reciprocal Rank Fusion（k=60）
  scoring.py                      -- 関連度%変換（相対値化。ADR-0010）
  hit_judge.py                     -- 「ヒットなし」判定（反対側BM25=0件 かつ 類似度<基準値。ADR-0008）
  rephrase.py                       -- 言い換え候補生成（F-21）
  highlight.py                       -- 一致理由の語句ハイライト（検索結果上位のみ都度計算。F-18、ADR-0018）
db/
  schema.sql                          -- documents/tech_usage/evaluations/patents/documents_fts/embeddings/
                                         search_logsの定義
  build_db.py                          -- schema.sql＋fixtures/*.jsonから起動時にDBを自動構築（.dbはGit管理外）
  repositories.py                       -- 各テーブルへのCRUD関数群
  logging.py                             -- search_logsへのINSERT（st.buttonブロック内でのみ呼ぶ）
ingest/
  summarize.py                             -- 【開発時に手動で1回だけ実行】seed文書の「平たく言うと」要約を
                                               生成し、fixtures/*.jsonのsummary_plainへ書き戻す（ADR-0020）
  embed_batch.py                            -- 【起動のたびに自動実行】全文書の`title`/`body`/`problem`/
                                               `background`をフィールドごとに埋め込みembeddingsへ保存
                                               （ローカル無料計算。ADR-0020・0021）
  crawler.py                                 -- requests＋BeautifulSoupでの定期クロール、content_hashで差分検知（F-11）
  local_folder_crawler.py                     -- ローカルフォルダ巡回デモ版（ダミーWord/PDF取り込み。F-12）
  patents_import.py                            -- 手動転記した特許データ（INPITで候補選定→J-PlatPat原本）を投入
fixtures/
  seeds.sql                                     -- 手入力データの正本（documents/tech_usage/evaluations/
                                                   patents）。knowledge.dbから書き出したテキスト（ADR-0025）
tools/
  export_seeds.py                                -- knowledge.db → fixtures/seeds.sql の書き出し（コミット前に1回）
  check_gap.py                                    -- BM25が0件になるデモ用クエリの実測（N-06・U-04）
.github/workflows/crawl.yml                        -- 夜間バッチでcrawler.py→summarize.py→embed_batch.py→DB更新（F-11）
tests/
  test_cross_search.py                                -- RRF統合、双方向検索（同じ側/反対側）のテスト
  test_hit_judge.py                                     -- ヒットなし判定の閾値テスト、デモ文でBM25=0件になることの確認（ADR-0011）
  test_scoring.py                                         -- 関連度%変換のテスト
```

## データ

- **手入力データの編集先は`knowledge.db`本体**（DBツールで直接編集）。コミット前に
  `tools/export_seeds.py`で`fixtures/seeds.sql`へ書き出し、そのテキストをGitに乗せる（ADR-0025）
- `knowledge.db`はリポジトリに含めない。`.db`が無いとき`db/build_db.py`が`schema.sql`と
  `fixtures/seeds.sql`から組み立てる。`.db`があるときは手元の編集を守るため何もしない。
  `git pull`後に取り込み直すときは`python3 db/build_db.py --rebuild`（ADR-0015・0025）
- 埋め込みベクトルは`embed_batch.py`が事前に一括計算し、`embeddings.vec`にBLOB（`numpy.tobytes()`）
  で保持する。検索時にクエリ側のベクトルだけその場で計算する（仕様「入力と出力」F-02）
- `search_logs`はアプリ実行中のプロセス内でのみ確実に残る（Streamlit Community Cloudの制約。仕様
  「保存先の方針」）。デモ手順書に「アプリを再起動しない」旨を明記する
- シーズ文書（`source='patent_manual'`）・ニーズ文書（`source='dummy'/'faq'`）は`fixtures/`の
  JSONとして固定し、`patents_import.py`等の取り込みスクリプトで`documents`へ投入する（仕様
  「データソースの方針」）。訴求の競合チェック（旧F-20）は対応しないため訴求文書は扱わない（ADR-0019）
- **`summary_plain`は`knowledge.db`に入れておく**（開発時に`summarize.py`を手動で1回実行して生成・
  レビューし、`seeds.sql`へ書き出す）。デプロイ・起動時にAPIは呼ばない（ADR-0020）
- **埋め込みベクトルは`fixtures/`には含めない。** DBを組み立てるたび（起動のたび）に`embed_batch.py`が
  ローカルで再計算し`embeddings`へ保存する。ローカル無料計算のため毎回計算し直しても問題ない（ADR-0020）
- 一致理由ハイライト（F-18）の語句単位ベクトルは事前保存せず、検索結果上位の文書に対してのみ
  `search/highlight.py`が都度計算する（ADR-0018）

## 処理の流れ

**起動時**
`app.py`起動 → `db/build_db.py`が`knowledge.db`の有無を確認 → 無ければ`schema.sql`でテーブル作成
→ `fixtures/seeds.sql`を読み込み投入（`summary_plain`は生成済みテキストをそのまま入れる。APIは呼ばない）
→ `ingest/embed_batch.py`が全文書の埋め込みを計算し`embeddings`へ保存（ローカル無料計算。ADR-0020）
→ `st.tabs()`でタブ①②を表示

**データ準備時（開発時に手動で1回。デプロイ前）**
特許の発明の名称・要約・背景技術・課題をJ-PlatPatから手動転記し**`knowledge.db`へ直接入力**
（ADR-0021・0025） → `ingest/summarize.py`を手動実行し一言要約を生成・レビュー →
`tools/export_seeds.py`で`fixtures/seeds.sql`へ書き出し → コミット（ADR-0020・0025）

**検索（タブ①、仕様「入力と出力」F-02〜F-07・F-16・F-18・F-21）**
1. 立場切替ボタン（R&D／マーケ）で`query_side`・`user_dept`を`st.session_state`に設定（F-07）
2. 企画案の文章を入力し検索ボタン押下
3. `search/cross_search.py`が`bm25.py`（対象`doc_type`で上位50件）と`vector.py`（フィールド別ベクトル
   と比較し、doc_idごとに最大類似度を採ってから上位50件。ADR-0021）を実行
4. `search/rrf.py`で統合（k=60）→上位10件を**候補集合として選定**。表示順は後段で関連度の降順に並べ替える（ADR-0023）
5. `search/hit_judge.py`が「ヒットなし」を判定（反対側BM25=0件 かつ 類似度<基準値）
   - ヒットなしの場合も候補は空にしない → `rephrase.py`で言い換え候補を生成し、カードリスト上部に表示
     （仕様「タブ①検索」「エラー時の挙動」）
   - 裏側では`hit_count=0`で`db/logging.py`が`search_logs`へ記録 → タブ②「まだ社内に無い技術」に
     反映される
6. `search/scoring.py`が関連度%に変換、`search/highlight.py`が語句ハイライトを算出
7. `ui/cards.py`が1件ずつカードを描画（一言要約・権利状況・使用実績はDBから結合取得）
8. `db/logging.py`が`st.button`のブロック内で`search_logs`へINSERT（F-04。ボタン外に書かない）

**技術データベース（タブ②、仕様「入力と出力」F-05・F-08・F-17・F-19）**
1. 絞り込み条件（未使用の技術／特許ステータス／まだ社内に無い技術）を選択
2. `ui/tab_techdb.py`が`db/repositories.py`経由で`documents`/`patents`/`tech_usage`/`evaluations`/
   `search_logs`を条件でフィルタし一覧表示
3. 1件クリック→詳細画面：エビデンス（原文リンク・`evaluations`の評価済み／見送り／未評価・
   `patents`の関連特許。ADR-0022）・使われ方（`tech_usage`）・求めている声（反対方向の
   `cross_search`）を表示（訴求の競合チェックは対応しない。ADR-0019）

**データ取り込み（バッチ、仕様「入力と出力」F-01・F-11・F-12）**
`.github/workflows/crawl.yml`が夜間に`ingest/crawler.py`（差分検知）→`ingest/summarize.py`
（seed側のみ・登録時1回）→`ingest/embed_batch.py`の順で実行し、DBを更新する
